# Hackathon compliance notes

Use this checklist against the current event guide before submission. The project cannot manufacture the required evidence; the participant must supply it from the actual IBM Bob build.

## IBM Bob requirements from the event guide

- Bob IDE is required and must be a core component of the demonstrated solution workflow.
- For every Bob task related to the submission, provide the required task-session summary screenshot in `bob_sessions/`.
- Keep required Bob evidence in the final repository; do not create fake screenshots or histories.
- Use only compliant datasets/data sources. The event guide excludes client data, company-confidential data, personal information, and social-media data. Public web data must have terms that allow the intended use.
- The guide notes a finite Bobcoin allocation, so use Bob tasks deliberately and monitor consumption.

## Platform submission

The general lablab submission guidance calls for a working online prototype, a video presentation, a pitch deck, and a public GitHub repository. Verify the exact fields and limits shown in the current submission form at the time you submit.

## Project-specific proof

ReviewSentinel can demonstrate:

## Do not claim without evidence

Do not publish invented benchmark improvements, fabricated Bob usage, fake user counts, fake deployment URLs, or unsupported claims about customer impact.
